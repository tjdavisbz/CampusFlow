- The current `SAGU_Chapel_ImportOdysseyScans` reads `D:\SAGU SSIS Projects\Chapel\Import\ChapelAttendanceDaily.csv` with `OPENROWSET` and inserts distinct rows into `SAGU_Odyssey_ChapelScans`. - The current `SAGU_ChapelPresentStudents` joins `ID_Number` directly to `Student.StudentID` (the old SSN-derived join is commented out). For each chapel event, an early scan is from 20 minutes before through 5 minutes after start; a late scan is from 6 minutes after start through end; a checkout-window scan is from 30 minutes before end through one hour after end. Early scan plus checkout-window scan becomes Present; late scan plus checkout-window scan becomes Absent with `Late`; early scan without checkout-window scan becomes Absent with `Scan In Only`. The checkout flag predicates are commented out after the cloud Odyssey upgrade: timing, not the flag, drives classification. These are actual application-data writes, not temp-table-only routines.

It also marks eligible dorm devotional rows Present and updates recurring weekday excuses for non-residential students based on early class schedules. ## Implementation guardrails

- Use new PostgreSQL tables and an auditable, repeatable import. Store a file/run identity and raw scan identity so retrying an SFTP file does not duplicate attendance.
- Do not reproduce the legacy job's unconditional remote `rm *.csv` behavior. Download to a temporary location, validate the file, record a checksum and processing state, and retain an archival copy before marking or removing a remote file. Remote deletion should be an explicitly configured final step, after a durable successful import, not part of the download step. Preserve the pinned host-key verification and keep SFTP credentials in a secret store.
- The WinSCP command downloads **all** CSV files, while the SQL procedure reads only `ChapelAttendanceDaily.csv`; the replacement must account for every downloaded file and reject unknown filenames rather than silently delete them.
- Validate student identity, term, chapel event, and timestamp before applying a scan. Quarantine ambiguous/unmatched rows for review.
- Preserve current activity behavior: do not exclude `HCC Attendance` by name. It may satisfy the same scheduled-event scan windows as `Chapel Attendance`; an activity row outside those windows earns no attendance credit. Keep `Activity` and terminal in the import audit for investigation.
- Keep manual staff overrides distinct from imported decisions and never silently overwrite them.
- Enforce the student page against the authenticated student profile only; admin pages require a dedicated chapel permission.
